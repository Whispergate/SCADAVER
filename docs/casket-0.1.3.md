# casket 0.1.3: what changed and what scadaver does about it

casket is the skeleton, scadaver is the application. A casket change is finished only when this page
says what scadaver does about it.

## Why 0.1.3 exists

0.1.2 was built from a tree that predated `04d1046 "Make library output capturable"`, so the published
crate had no `src/core/output.rs` and would have reverted the output-capture feature. It was yanked.
0.1.3 is the same work rebased onto `04d1046`, with the feature intact and `output.rs` rewritten to
satisfy current clippy.

## What landed in casket 0.1.3

- `casket::Error` and `casket::Result`, with variants `Io`, `Timeout`, `Protocol`, `Auth`,
  `Unsupported`, exported at the crate root and through `casket::prelude`.
- `casket::capabilities::capabilities()`: a 16-row table (`Capability { protocol, read, write, notes }`)
  that answers, as data, which protocols expose read and write paths.
- `casket::core::client::DeviceClient`: a two-method trait (`device_info`, `close`), implemented by the
  IEC-104 session.
- Six runnable examples: `detect`, `read_modbus`, `write_modbus`, `loopback_modbus`, `capabilities`,
  `custom_vendor`. CI builds and runs them, so they cannot rot.
- `scripts/api-surface.sh` and `scripts/check-module-shape.sh`.
- `docs/errors.md`, `docs/architecture.md`, and a README whose support matrix is generated by
  `cargo run --example capabilities`.
- 31 new tests since 0.1.1 (231 to 262).

## Adopted here

- `Protocol::capability()` and `Protocol::supports_write()` in `src/protocol.rs`. The join is explicit
  rather than a slug comparison, because scadaver spells two protocols differently from casket
  (`fins` for Omron, `s7` for Siemens).
- `write` and `write_notes` in the `/api/protocols` payload built by `web_protocols()` in
  `src/web/routes.rs`.

## Deliberately not adopted yet

- **`casket::Error` in the surfaces.** They still return `Result<(), String>` and print through their
  own collectors. `anyhow` absorbs the new type, so nothing breaks today. Adoption becomes worthwhile
  when the mutating-verb predicate moves into casket, because then error variants and the safety gate
  share one vocabulary instead of two.
- **`DeviceClient` in scadaver's ops layer.** No `src/ops` module holds a session object; each call is
  open, act, drop. There is nothing to implement the trait on until one does.
- **`capabilities()` in the CLI.** The `set` subcommands are per-protocol nouns (`WriteCoil`,
  `WriteRegister`, …), not a `Protocol` value, so a guard there needs a noun-to-protocol map first.
  The web catalog was the cheap, honest first consumer.

## Reading the `write` flag

`write: true` means a `write_*` function exists, exactly 7 of 16 rows. It does not mean "this protocol
can change state": SNMP (`set`), MQTT (`publish`), IEC-104 (`single_command`) and Schneider
(`force_output_bit`) all change state without a `write_*` function and report `write: false` on
purpose. Any UI that renders this flag must carry `write_notes`, or it will mislabel four protocols.
